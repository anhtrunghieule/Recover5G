# Recover5G artifact

This folder is the reproducibility artifact for the MobiSys 2027 paper **Recover5G: Understanding Residual State after 5G Core Restarts**.

It holds the measurement harness, the experiment recipes, the per-run records with their captures and logs, the evaluators, the scripts that turn records into every number of the paper, and the container images of the systems under test. It does not hold the manuscript.

There are two ways to use it.

1. **Quick check.** It runs offline on any machine with Python 3.9 or newer. It regenerates the paper's numbers, figure data and generated tables from the included records and compares them with the paper. It takes about 2 seconds, or about 2 minutes with `--from-raw`.
2. **Full reproduction.** It reruns the experiments on an arm64 Linux Docker engine. Each experiment takes between 20 minutes and 10 hours of wall time.

## 1. What the artifact contains

| Part | Folder | Content |
|---|---|---|
| Quick check | `check_values.py`, `expected/` | The checker script. `expected/paper_values.json` and `.csv` list every number the paper typesets from a generated macro (2,139 `\Rx` keys and 69 named macros), plus figure data and generated table rows. |
| Revision workspace | `workspace/` | The experiments of 25 to 27 November 2026 that the paper reports: harness, recipes, records, captures, logs, evaluators, analyses and macro generators. Its layout is the one the scripts expect, so they run in place. |
| Earlier package | `reproduction/` | The reproduction package of 26 November 2026. It holds the arm64 image archive, image and package manifests, the frozen 26 November evidence (main-campaign replay, reject-teardown reconstruction, accumulation chains, historical artifact with the issue study and timer facts), the fresh-validation cohort and its blank assessment packet. It has its own `README.md` and `RELEASE-MAP.md`. |
| Environment | `environment/` | `pins.json` with every commit, image tag and image ID. `f12-repair.diff` is the orphan-session repair. |
| Tools | `tools/extract_expected.py` | The script that produced `expected/` from the manuscript sources. Reviewers do not need it. |
| Provenance | `MANIFEST.sha256` | SHA-256 of every file in this folder. |

Two terms recur below. A **recipe** is a controlled fault sequence repeated a few times, such as the orphan-session recipe. A **cohort** is a set of runs fixed by a design file written before its first run, such as the clean rerun. Every cohort folder under `workspace/results/raw/` holds one JSON record per run (`*.jsonl`), the capture of each run (`pcap/*.pcap.gz`), the NF logs (`logs/`) and, for the cohorts of 26 and 27 November, a `DESIGN.md` with the hypotheses, run counts and exclusion rules fixed in advance and the outcomes recorded afterwards.

### Experiment in the artifact that the current manuscript does not cite

* **Kill timing** (`killtime.py`, `job_killtime.sh`, `results/raw/killtime`, `killtime_eval.py`). It varies only the delay between the trigger line and the kill (0, 5, 20 ms; 60 runs). Persistent 4, 9 and 18 of 20; 31 of 31 runs killed after the AMF sent the accept are persistent and 0 of 29 before. `gen_macros_rev28b.py` emits these as `kt-*`, but no `\Rx{kt-...}` appears in the manuscript. The paper's account of kill timing (`a3-st-*`) is read from the delay and clean-rerun records instead.

## 3. Requirements

### Quick check

* Python 3.9 or newer, standard library only (tested with 3.9.6, 3.10 and 3.15). Any operating system with a POSIX shell.
* 3 GB free disk for the working copy with `--from-raw`, 100 MB without.
* No Docker, no network.

### Full reproduction

* **Host.** Apple Silicon Mac with Colima, or an arm64 Linux host with Docker Engine and the Compose plugin. The paper's runs used an Apple M5 Max with 64 GiB, Colima 0.10.3 with Apple Virtualization, and Ubuntu 24.04 guests with kernel 6.8.0-117. An x86-64 host would need every image rebuilt for amd64. That path is untested.
* **Kernel features in the Docker VM.** SCTP (`modprobe sctp`) for NGAP. `/dev/net/tun` for UERANSIM and OAI UEs. The `gtp5g` 0.9.14 kernel module for free5GC's UPF (tarball in `workspace/free5gc/`). Root in the VM for the kill placer (`testbed/r5g/placer.py` runs through `colima ssh ... sudo`).
* **Shared path.** The harness mounts configuration files from the host into containers and runs the placer from the host path inside the VM. Keep the artifact under your home folder, which Colima mounts at the same path.
* **Network** for pulling free5GC and OAI images and for building the images that are not in the archive (section 5, step 4).
* **Python 3.9 or newer** on the host, standard library only. `caffeinate` (macOS) only to keep the host awake.

| VM (Colima profile used in the job files) | vCPU, RAM | Disk | Experiments |
|---|---|---|---|
| `r5g-claude` | 6, 12 GiB | 100 GiB | main rerun, held-out, delay (one and three seeds), clean rerun, kill timing, orphan and cross-UE recipes |
| `r5g-claude-ran` | 4, 8 GiB | 100 GiB | OAI RAN, free5GC control and orphan chains (gtp5g), from-source rebuild, before and after fixes, organic chains, impact |
| `r5g-claude-big` | 8, 16 GiB | 100 GiB | thousand-UE chains |
| `r5g-reproduction` | 4, 4 to 8 GiB | 35 GiB | earlier package: orphan smoke test, fresh-validation cohort, replays |

The disk sizes allow for VM image growth (section 10). The artifact itself is about 2 GB.

## 4. Quick check

```sh
cd artifact
python3 check_values.py                 # about 2 s
python3 check_values.py --from-raw      # about 2 min
```

The quick mode copies `workspace/` to `out/work/` and runs every macro generator on the included summary files. It also recomputes the convergence correction, reruns the historical artifact's `render.py`, rescores the reject-teardown reconstruction and re-renders the fresh-validation table. `--from-raw` first reruns 47 offline evaluators and analyses on the per-run records: orphan, cross-UE, held-out and delay evaluators, the trace reference (`wire_truth.py`), the identity reference on cached decodes (`idref_eval.py --no-decode`), the main, impact, delay, before-and-after, organic, thousand-UE, PFCP and kill-timing evaluators, the clean-rerun scoring, and the analyses in `analysis-r1/` and `analysis-r3/` (including the parse of the decoded organic captures, about 60 s).

Every step runs on the copy. `docker`, `pmset`, `colima`, `tshark` and `caffeinate` are replaced by stubs that fail, so no step can reach a container runtime or the host's power log. Outputs:

* `out/quickcheck_summary.txt`: counts and every difference.
* `out/quickcheck_report.json`: one entry per paper value with expected and obtained values, plus the steps with their logs.
* `out/generated/<generator>/`: the regenerated macro files.

The exit status is 0 when every regenerable value matches. Expected outputs from the authors' runs are in `expected/sample-output/`.

### Expected result

Quick mode, as run on 28 November 2026:

```
Regenerable paper values: 1706 of 1706 match
Figure data and generated tables: 43 of 43 match
Not regenerated: 485 values of the earlier rerun campaign, 17 values of the machine-reader experiment
```

With `--from-raw`, 1690 of 1706 values match and 43 of 43 figure and table checks match. The 16 differences are explained in section 9. Of the 884 values in the main paper (877 `\Rx` keys and 7 named macros), 880 are regenerable and all 880 match in quick mode.

## 5. Setup for full reproduction

Commands run from the artifact folder unless noted. Never change the global Docker context; every script passes `DOCKER_CONTEXT` or `--context` itself.

**Step 1. Create the VMs.** With Colima, use separate profiles and `--activate=false`:

```sh
colima start r5g-claude     --arch aarch64 --vm-type vz --cpu 6 --memory 12 --disk 100 --activate=false
colima start r5g-claude-ran --arch aarch64 --vm-type vz --cpu 4 --memory 8  --disk 100 --activate=false
colima start r5g-claude-big --arch aarch64 --vm-type vz --cpu 8 --memory 16 --disk 100 --activate=false
for p in r5g-claude r5g-claude-ran r5g-claude-big; do colima ssh -p $p -- sudo modprobe sctp; done
```

On arm64 Linux without Colima, create Docker contexts with the same names (`colima-r5g-claude` and so on) or edit `DOCKER_CONTEXT` in the job files. The kill placer calls `colima ssh -p <profile>`. Without Colima, replace that call in `testbed/r5g/place.py` with a root shell on the Docker host.

**Step 2. Verify the package and load the archived images** into each context that needs them:

```sh
python3 reproduction/reproduce.py verify
python3 reproduction/reproduce.py load --context colima-r5g-claude
python3 reproduction/reproduce.py load --context colima-r5g-claude-ran
python3 reproduction/reproduce.py load --context colima-r5g-claude-big
```

`load` imports `r5g/open5gs:e85748e`, `r5g/open5gs:e85748e-f12repair`, `r5g/open5gs-build:base`, `r5g/ueransim:4f45e18-p2`, `r5g/tshark:1` and `mongo:7.0`, then checks each image ID against `reproduction/manifests/images.json`.

**Step 3. Generate the stack configurations.** Each stack (instance 1 to 8) has its own compose file and addresses:

```sh
cd workspace/testbed && for i in 1 2 3 4 5 6 7 8; do python3 inst.py gen $i; done
```

The generated files for the runs reported in the paper are already in `testbed/inst/`.

**Step 4. Build or obtain the images that are not in the archive.**

```sh
D=workspace/testbed/docker
# Toolchain image for upstream builds. The runs used a from-source rebuild (workspace/build/rebuild/job_rebuild.sh).
# Retagging the archived build image is a documented shortcut: same commit and toolchain, different build date.
docker --context colima-r5g-claude-ran tag r5g/open5gs-build:base r5g-rebuild/open5gs-build:e85748e
for c in ce6444f1b0a776843e78320b13a41fb39bf5ed9c 097162c4225bdb3d86ab17eb5119a0aae15c5490; do
  docker --context colima-r5g-claude-ran build -f $D/open5gs/Dockerfile.upstream --build-arg OPEN5GS_COMMIT=$c \
    -t r5g/open5gs:${c:0:7} $D/open5gs
done
# UERANSIM with the gNB that redoes NG Setup, under the tag used by the organic, scale, impact and free5GC runs.
docker --context colima-r5g-claude-ran tag r5g/ueransim:4f45e18-p2 r5g-rebuild/ueransim:4f45e18-p2
# Stock UERANSIM gNB (main rerun, stock-gNB arms): build from source.
docker --context colima-r5g-claude build -f $D/ueransim/Dockerfile -t r5g/ueransim:4f45e18 $D/ueransim
docker --context colima-r5g-claude tag r5g/ueransim:4f45e18 r5g/ueransim:4f45e18-p1
# free5GC and OAI
for nf in nrf amf ausf nssf pcf smf udm udr chf webui upf; do docker --context colima-r5g-claude-ran pull free5gc/$nf:v4.0.1; done
docker --context colima-r5g-claude-ran pull free5gc/smf:v4.3.0
docker --context colima-r5g-claude-ran pull oaisoftwarealliance/oai-gnb:2025.w40
docker --context colima-r5g-claude-ran pull oaisoftwarealliance/oai-nr-ue:2025.w40
```

Copy or load the images into every context whose job files use them (`docker save | docker --context ... load`). The build logs of the images used in the paper are in `workspace/results/raw/upfix/build-logs/`. Their short IDs are in `environment/pins.json`. A rebuild gets a different image ID. `/COMMIT` inside each image names its source commit and patches.

**Step 5. Build and load gtp5g in the free5GC VM** (again after every VM restart):

```sh
cp workspace/free5gc/gtp5g-v0.9.14.tar.gz ~/ && colima ssh -p r5g-claude-ran -- sh -c '
  sudo apt-get install -y build-essential linux-headers-$(uname -r) &&
  tar xzf ~/gtp5g-v0.9.14.tar.gz -C /tmp && cd /tmp/gtp5g-0.9.14 && make && sudo make install && sudo modprobe gtp5g'
```

**Step 6. Environment.** Job files compute the workspace path from their own location. You can override it with `R5G_WORKSPACE`. `workspace/env.sh` sets `DOCKER_CONTEXT` (default `colima-r5g-claude`), `UERANSIM_IMAGE` and `R5G_OUT` for the jobs that source it. Other variables: `R5G_INST` (stack 1 to 8), `R5G_UE_SEP=1` (one container per UE), `R5G_CAP_FILTER` (capture filter).

**Step 7. Write new results to a new folder.** The job files write into `workspace/results/raw/<cohort>/` and append to its records. To keep the shipped records intact, copy `workspace/` first, or set `R5G_OUT` to an empty folder and adjust the job file's `R5G_OUT` line. Then run the evaluator on that folder (section 6).

## 6. Full reproduction, one experiment at a time

Wall times are from the documented host. Machine hours are summed run durations. Each job prints the start and end time. Run `pmset -g log | grep -E ' Sleep  | Wake  | DarkWake  '` afterwards on a Mac, add the intervals to `workspace/results/host_sleep_intervals.json` with `testbed/exp/hostsleep_refresh.py`, and let the evaluators exclude runs that overlap a sleep. The evaluators read the records in the cohort folder and write their summaries beside them. Then rerun `python3 check_values.py` on the modified workspace (copy it into `artifact/workspace` of a scratch copy of the artifact) to regenerate the macros.

Outcomes are judged by the rules in each `DESIGN.md`. A rerun on another host should reproduce the qualitative outcomes (residue or not, which pool fills, which arm differs). Exact counts can differ, because kill placement races with the NFs.

### 6.1 Orphan sessions and the repair (Table 4)

```sh
bash workspace/testbed/exp/job_orphan.sh 1 r5g/open5gs:e85748e base          # VM r5g-claude, stack 1
bash workspace/testbed/exp/job_orphan.sh 2 r5g/open5gs:e85748e-f12repair repair
bash workspace/testbed/exp/job_orphan_oai2.sh                                 # OAI gNB and UE, VM r5g-claude-ran
cd workspace/testbed && python3 exp/orphan_eval.py ../results/raw/orphan ../results/raw/orphan-oai \
  && python3 exp/wire_truth.py ../results/raw/orphan --kind orphan && python3 exp/orphan_ref_eval.py ../results/raw/orphan
```

Runs: 5 faulted runs per build and gNB behaviour, 3 no-fault runs per build. About 1.5 machine hours, under 1 hour wall per batch. Expected: residue at both checkpoints in every faulted baseline run and in no repaired or no-fault run; working new sessions in all; accepted PFCP deletions of the old sessions only with the repair. The OAI batch must use the capture filter `not port 27017 and not port 9090 and not tcp port 4043` (section 10).

* Records excluded from a result (harness errors, host-sleep overlaps, pilots, invalid chains) are kept on disk. Each evaluator lists them in its summary.

Changes made while assembling this artifact, all on copies:

* Absolute paths of the authors' home folder were replaced by relative paths or by `$R5G_WORKSPACE` in 71 code files and in the error tracebacks of `results/raw/timing/timing_{g10,g150,v150}.jsonl` (shown as `<WORKSPACE>`).

## 9. Known limitations and deviations

* **Values this artifact cannot regenerate.** 485 values come from the earlier rerun campaign of 10 to 19 November 2026 (`generated-rerun/` in the manuscript, synced from repository commit 9c9d721): 4 in the main paper (`ps-n` = 228, `s-ps3-n` = 120, `s-ps3-space` = 1626, `\RrBtSeeds` = 5; the first three also appear in the supplementary appendix) and 481 more in the supplementary appendix only. Their records and generators were produced on another host and are not here. 17 supplementary values (`ar-*`) come from the machine-reader experiment, which is not distributed. Typed tables without a generator (standards, case ledger, closest tools, built parts) are not regenerated.
* **Differences that appear only with `--from-raw`.**
  * 13 supplementary values `v25-tr-*` (trace reference on the one-seed delay cohort). The shipped `timingref_*` outputs were computed at 18:06 on 25 November, before 61 sleep-affected delay runs were repeated (20:14). Rerunning on the final records gives, for example, 216 instead of 155 runs. The other delay values (`v25-tm-*`) were recomputed after the repeats and match.
  * `a3-cost-scale-hours` (1.9, obtained 3.1) and `a3-cost-total-hours` (133.9, obtained 135.2): the analysis ran before the UDM-raised and capture chains were added.
  * `a3-pv-scale-sha`: `results/raw/scale/DESIGN.md` was amended with follow-up C after the analysis recorded its hash.
  * `paper/cost.py` is not rerun. It sums every record file and does not parse the record formats of the later cohorts. `results/cost.json` is kept as computed on 25 November.
* **Convergence correction.** The paper's held-out convergence maximum (33.05 s) applies the stricter convergence rule of the earlier package (`r5g/verdict.py`, `first_stably_clean`) on top of the workspace's held-out evaluator with host-sleep exclusion. The workspace evaluator alone gives 32.61 s. `check_values.py` applies the rule to a copy and reproduces 33.05 s.
* **Host sleep.** The host entered maintenance sleep while idle, which freezes the VMs and advances the host clock. Evaluators exclude every run whose duration overlaps an interval in `results/host_sleep_intervals.json` (from `pmset -g log`), keep it on disk, and use a clean repeat when one exists. Sleep intervals after 27 November are not recorded.
* **Single host.** Every cohort of the evaluation ran on one Apple M5 Max in aarch64 VMs that also ran other VMs. The earlier campaign's host is unresolved (the paper discusses this). No physical RAN or UE was used.
* **Automated verdicts.** The checker, the identity reference and the trace reference are automated. The reference shares some readouts with the checker and uses source-derived rules. No person independent of this work has labelled a run. The blank assessment packet is in `reproduction/evidence/validation-20261126/expert-packet/`. Its private keys and frozen predictions, and the 36-case adjudication sample of `analysis-r1/` with its key, are withheld so that the packet can still be used blind.
* **Issue-study labels.** The audit labels in `issues-audit/labels/` were assigned by an AI assistant and were not checked by a person. The first-pass and second-pass labels of the historical study are tool-assisted.
* **Images.** The archive holds the images of the pinned build, the repair, the toolchain, the patched UERANSIM gNB, tshark and MongoDB. The before-fix and fixed Open5GS builds, the stock UERANSIM gNB and the rebuild tags must be built (section 5), and free5GC and OAI images are pulled from Docker Hub. Their image IDs will differ from the build logs. Old Dockerfiles use Ubuntu package mirrors that change over time.
* **Literal values.** A few figure coordinates are typed in the figure source (Figure 3b: 16 and 4). They equal generated keys (`f5-q3-*`, `f5-q3fix-*`).

## 10. Known traps

* **VM disk growth.** Container churn grows a Colima VM's disk image by about 50 GB per hour of campaign. Run `colima ssh -p <profile> -- sudo fstrim -a` between batches, and check free host disk before long jobs.
* **caffeinate and `wait` deadlock.** `job_upfix.sh`, `job_timing2.sh` and `job_main_rerun.sh` start `caffeinate -i -s -w $$ &` and later call a bare `wait`. The `wait` also waits for `caffeinate`, which waits for the script, so the job never exits after its runs finish. Replace the line with `caffeinate -i -s -t <seconds> &`, or `wait` on the worker PIDs only, and check the row count of the record file rather than the exit of the job.
* **OAI capture filter.** An OAI RF-simulator run streams radio samples over TCP port 4043. A capture without `not tcp port 4043` in its filter drops control packets. The first OAI batch (`results/raw/orphan-oai-batch1-capture-unusable/`) has this fault and is not used.
* **gtp5g after restart.** The gtp5g module is gone after a VM restart; free5GC's UPF then fails to start. Reload it (section 5, step 5).
* **Host sleep.** Keep a Mac awake during campaigns (`caffeinate -i -s -t <seconds>`), record `pmset -g log` afterwards and let the evaluators exclude overlapping runs. `time.monotonic()` stops during sleep and `time.time()` does not.
* **Ubuntu mirrors.** `ports.ubuntu.com` and some mirrors time out intermittently during image builds. The Dockerfiles take `--build-arg UBUNTU_MIRROR=...`.
* **Shared Docker context.** Never switch the global Docker context. Start Colima profiles with `--activate=false`. `reproduction/reproduce.py` refuses the contexts of the original campaign.
* **Stock gNB.** The stock UERANSIM gNB aborts when the AMF dies. Recipes that use it restart the gNB from the harness.
